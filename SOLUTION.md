## Что сделано 

Сделано всё из частей 1–3 и одна доп. задача (поиск по клубу + тесты на фильтр):

- `useMatches` — загрузка с проверкой `response.ok` и формата ответа; ответы устаревших запросов игнорируются.
- Экран: крутилка при первой загрузке; ошибка с «Повторить»; пустой список. Если обновление упало, а данные уже есть, — старый список остаётся, над ним баннер с ошибкой.
- Карточка: команды, счёт, дата в поясе устройства, статус по-русски, звёздочка.
- Фильтр «Все / Предстоящие / Завершённые», поиск по клубу, кнопка «Обновить» + pull-to-refresh, «Обновлено N сек назад».

Не проверял в Expo Go на телефоне — только в браузере (`npm run web`).

## Решения

- **Статусы.** `scheduled`, `live`, `postponed` → «Предстоящие»: результата ещё нет, матч впереди или идёт прямо сейчас (в «Завершённые» `live` класть нельзя — счёт ещё изменится). `finished` → «Завершённые». Незнакомый статус (если сервер пришлёт новый) виден только во «Всех» с подписью «Статус неизвестен» — не теряется и не попадает не в ту вкладку.
- **`startsAt: null`** (перенесённый матч `m7`) — вместо «Invalid Date» пишем «Дата уточняется». Невалидную строку даты обрабатываем так же.
- **`live`** — показываем текущий счёт и минуту («Идёт, 67′»), статус выделен цветом.
- **`score: null`** — показываем «– : –».
- **Два «Динамо»** (Москва и Махачкала) — клубы и матчи различаем по `id`, `key` в списке — `match.id`, а не название.
- **Время.** API отдаёт UTC (`...Z`); `toLocaleString('ru-RU')` без `timeZone` переводит в пояс устройства.
- **Пустые состояния** различаются: «Матчей пока нет» / «В этой категории матчей нет» / «Ничего не найдено».

## Баги из части 2

1. **Звёздочки.** `isFavorite` был `Boolean(favorites.indexOf(id))`: для отсутствующего id `indexOf` даёт `-1`, а `Boolean(-1) === true` — поэтому горели все звёзды. А матч на позиции `0` в массиве, наоборот, считался «не избранным». Вторая проблема: `toggle` мутировал массив (`push`/`splice`) и передавал в `setFavorites` ту же ссылку — React сравнивает state по ссылке, решает, что ничего не изменилось, и не перерисовывает, поэтому нажатия срабатывали «непредсказуемо». → `includes(id)` и новый массив через функциональный `setFavorites(prev => ...)`; в `FlatList` добавил `extraData={favorites}`.
2. **«Обновлено N сек назад».** Колбэк `setInterval` создавался один раз (`useEffect(..., [])`) и замкнул `seconds = 0` из первого рендера, поэтому каждую секунду выставлял `0 + 1 = 1` — число застывало. Проп `since` не использовался вообще, так что после обновления сбрасывать было нечему; интервал ещё и не очищался. → Секунды считаются как `now - since`, интервал только обновляет `now`, эффект зависит от `since` и очищает интервал.

## Доп. задача

Выбрал **поиск по названию клуба** и **тесты на логику фильтра** — фильтр и поиск оказались в одной чистой функции `filterMatches`, её удобно покрыть тестами, а именно там сидят решения про статусы.

- Поиск по хозяевам и гостям, без учёта регистра, пробелов по краям и «ё»/«е»; сочетается с вкладкой.
- Тесты: `npm test` — встроенный `node:test`, без Jest (нужен Node 22.18+, который запускает `.ts` напрямую). Добавил dev-зависимость `@types/node` — только типы для `node:test`/`node:assert`, и `allowImportingTsExtensions` в `tsconfig.json`, чтобы в тесте можно было импортировать `./filter.ts` с расширением, как требует Node.
